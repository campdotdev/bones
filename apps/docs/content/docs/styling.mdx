title: Styling
description: Customize skeletons with CSS custom properties.

All skeleton visuals are controlled by CSS custom properties. Override them globally or scope them to a specific section.

## CSS custom properties

| Property           | Default                       | Description                                                             |
| ------------------ | ----------------------------- | ----------------------------------------------------------------------- |
| `--bone-base`      | the text color at 12% opacity | Skeleton background color                                               |
| `--bone-highlight` | the text color at 6% opacity  | Highlight color (for shimmer)                                           |
| `--bone-radius`    | `4px`                         | Border radius of skeleton bars. Must have a unit; write `0px`, not `0`. |
| `--bone-duration`  | `1.5s`                        | Animation duration                                                      |

The color defaults derive from the text color in effect at the skeleton, so bones contrast with whatever background the text around them is readable on. A `#333`-on-white article gets translucent dark bars. The same markup inside a dark card with light text gets translucent light bars.

## Theming

Override properties on any container to theme a section:

```tsx
<div
  style={{
    "--bone-base": "#f5e6d3",
    "--bone-highlight": "#faf0e6",
    "--bone-radius": "8px",
  }}
>
  <UserCard aria-busy="true" />
</div>
```

Or use a CSS class:

```css
.warm-skeleton {
  --bone-base: #f5e6d3;
  --bone-highlight: #faf0e6;
}
```

## Dark mode

Dark mode needs no configuration. Because bones derive from the text color, a dark theme's light text produces light bones, whether the theme comes from `prefers-color-scheme` or a class-based toggle.

To give dark mode different bones anyway, override the properties in your dark styles:

```css
.dark {
  --bone-base: rgba(255, 255, 255, 0.2);
  --bone-highlight: rgba(255, 255, 255, 0.1);
}
```

One case needs a manual override: text that depends on its background for contrast, such as white text over a hero image. If the image is part of what loads, the derived white bone can vanish against the page behind it. Set `--bone-base` on that section to a color that works without the image.

## Animations

Bones shimmer by default. Set `data-bones-animate` on an element to change the animation for the bones inside it. The attribute also works on a bone itself and on the `aria-busy` element of an automatic region.

- `shimmer` - horizontal highlight sweep (the default)
- `pulse` - gentle opacity fade (also kicks in automatically for `prefers-reduced-motion: reduce`)
- `none` - no animation

```tsx
{/* Pulse one section */}
<div data-bones-animate="pulse">
  <UserCard user={fetchUser()} />
</div>

{/* Keep every skeleton in the app still */}
<body data-bones-animate="none">
```

Speed is controlled by `--bone-duration`. Shimmer colors use `--bone-base` and `--bone-highlight`.

## Accessibility

- Bones only paint under `aria-busy="true"`, which is the attribute assistive technology already reads.
- `pulse` replaces `shimmer` for users who prefer reduced motion. `none` stays still.
- Skeleton pseudo-elements have `pointer-events: none`.
