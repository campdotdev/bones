---
title: bones-boundary
description: A custom element that manages the loading state of its subtree.
---

```ts
import "@camp.dev/bones/element";
```

`<bones-boundary>` sets `aria-busy="true"` and `inert` on itself while its subtree is loading, and removes them when it is not. It draws nothing. `@camp.dev/bones/css` styles `data-bone` markup wherever it appears, and unmarked leaves only inside an `aria-busy="true"` region.

Set `busy` when loading starts and remove it when loading ends. The element waits `delay` before it shows bones, so a fast response never flashes a skeleton, and it keeps bones for at least `min-duration`, so a slow one never strobes.

## Usage

```html
<link rel="stylesheet" href="https://unpkg.com/@camp.dev/bones/src/css/bones.css" />
<script type="module">
  import "https://unpkg.com/@camp.dev/bones/dist/element/index.mjs";
</script>

<bones-boundary id="profile" busy>
  <h2>Loading profile</h2>
  <p>Three lines of copy become three bones while busy.</p>
</bones-boundary>

<script type="module">
  await customElements.whenDefined("bones-boundary");
  const boundary = document.getElementById("profile");
  const response = await fetch("/api/profile");
  const profile = await response.json();
  boundary.querySelector("h2").textContent = profile.name;
  boundary.querySelector("p").textContent = profile.bio;
  boundary.busy = false;
</script>
```

The second script waits for the definition instead of trusting script order. A classic `<script>` in its place would run before the deferred module import above it and touch a boundary that has not upgraded yet. A property written before the upgrade is replayed when the upgrade happens, but a property read before it returns `undefined`.

## Attributes

| Attribute      | Property      | Type                    | Default  | Description                                                                                                      |
| -------------- | ------------- | ----------------------- | -------- | ---------------------------------------------------------------------------------------------------------------- |
| `busy`         | `busy`        | boolean                 | absent   | The subtree is loading.                                                                                          |
| `force`        | `force`       | boolean                 | absent   | Show bones now and keep them until removed. Skips both timers.                                                   |
| `delay`        | `delay`       | number (ms)             | `200`    | How long `busy` must stay set before bones show.                                                                 |
| `min-duration` | `minDuration` | number (ms)             | `400`    | Once shown, bones stay at least this long.                                                                       |
| `transition`   | `transition`  | `"auto"` or `"none"`    | `"auto"` | Whether hiding bones runs inside `document.startViewTransition()`.                                               |
| `precision`    | `precision`   | `"css"` or `"measured"` | `"css"`  | How bones are drawn while showing. `"measured"` draws per-line overlay bones measured from the rendered content. |

Every property reflects to its attribute. A `delay` or `min-duration` that is missing, negative, or not a number falls back to the default. The read-only `showing` property is `true` while bones are visible.

A new `delay` or `min-duration` applies to the next transition, not the one already running. The element reads each value once, at the moment it starts the timer.

## Output attributes

While bones show, the element carries `aria-busy="true"` and `inert`. `inert` removes the subtree from the tab order and from assistive technology, and ignores pointer events. Do not set these two attributes yourself on the client. The element puts them back if anything else removes them while bones are showing. Setting them on the server is how you render the loading state before JavaScript runs (see below).

`inert` blurs whatever was focused inside the boundary, and the element does not restore that focus when bones hide. Move focus yourself in a `bones:hide` listener if the interaction needs it.

An element that upgrades with `aria-busy="true"` already in its markup adopts the showing state, so `bones:show` fires on upgrade as well as after `delay`.

## Events

| Event        | When                                                            |
| ------------ | --------------------------------------------------------------- |
| `bones:show` | After `aria-busy` and `inert` are set.                          |
| `bones:hide` | After they are removed. A view transition may still be playing. |

Both bubble and cross shadow roots. Neither is cancelable.

```js
boundary.addEventListener("bones:hide", () => console.log("content visible"));
```

## The swap

When `busy` is removed and `min-duration` has elapsed, the element removes its output attributes inside `document.startViewTransition()`, which crossfades bones into content. The call is skipped when `transition="none"` is set, when the browser has no `startViewTransition`, or when `prefers-reduced-motion: reduce` matches. In every case the content appears.

Two limits of the View Transitions API apply:

- The API snapshots the whole document. If two boundaries hide within the same crossfade, the browser skips the first transition and runs the second.
- The page does not respond to input for the length of the crossfade. Set `transition="none"` on boundaries where that matters.

## Server rendering

Render the output attributes yourself when you know a region is loading at request time:

```html
<bones-boundary busy aria-busy="true" inert>…</bones-boundary>
```

The stylesheet paints bones and the subtree is inert before the element upgrades. On upgrade the element adopts the showing state, and `min-duration` counts from that moment. With `precision="measured"`, the leaf bones the stylesheet painted before JavaScript ran are replaced by measured bars at upgrade time; the swap is the enhancement taking over.

## Streaming

A server can stream into a boundary: render it busy in the shell with a `data-bones-slot` id, then flush the real content later in the same response. The swap script replaces the children and clears `busy`, so the reveal runs through `min-duration` and the view transition exactly as a client-side `busy = false` does. A failed region gets `data-bones-error=""` and keeps its fallback children unless the server sent error content; style it with `bones-boundary[data-bones-error]`. The element never reads either attribute — they belong to the [wire protocol](/streaming).

## Measured bones

With `precision="measured"`, the element measures its rendered content while bones show and draws the skeleton from the measurements: one bar per rendered line of text, one block per image or form control. Bars live in a shadow root, so page CSS and frameworks never see them; style them with `::part(bone)`, `::part(bone-text)`, `::part(bone-block)`, and `::part(overlay)`, or through the `--bone-*` custom properties, which inherit into the overlay.

While the overlay shows, the element sets `data-bones-measured` and, unless the author already set it, `data-bones-auto="off"` on itself. It hides the content with inherited `visibility` and re-measures whenever its size changes. When it hides, the attributes the overlay set come off inside the same swap that removes `aria-busy`; an author-set `data-bones-auto` is never touched. If there is nothing to measure — an empty boundary, or an environment without layout — the element stays on the CSS path and the stylesheet draws leaf bones instead.

A measured boundary is `display: block; position: relative` (the overlay needs a positioned block container). This applies from upgrade, not from the first show.

Three edges to know about:

- Content hiding uses a non-`!important` `::slotted` rule. An author rule that sets `visibility` on a direct child of the boundary wins over it and that child stays visible. The same cascade behavior is what lets the stylesheet keep `[data-bones-auto="off"]` subtrees visible under the overlay. Without the stylesheet on the page, opted-out subtrees hide with everything else.
- Re-measurement is driven by size changes and by DOM changes: children added, removed, or replaced, and text edits. An attribute change that reflows content without either — a `class` swap inside a fixed-size boundary — keeps its previous bars until the next resize or DOM change. Content that scrolls inside the boundary (an `overflow: auto` box) also leaves bars at their pre-scroll positions, because scrolling fires neither. A subtree that becomes empty while showing drops the boundary to the CSS path for the rest of that showing window, even if content is added later.
- Measurement compensates for scale transforms on the boundary or its ancestors, but not for rotation or skew. A rotated boundary draws its bars in the wrong place.

## React

`@camp.dev/bones/react` exports a typed wrapper. Import the element once in a client entry so the tag is registered.

```tsx
import "@camp.dev/bones/element";
import { BonesBoundary } from "@camp.dev/bones/react";

function Profile({ loading, user }: { loading: boolean; user?: User }) {
  return (
    <BonesBoundary busy={loading} minDuration={600} onHide={() => track("profile:visible")}>
      <h2>{user?.name ?? "Loading"}</h2>
      <p>{user?.bio ?? "Three lines of copy become three bones while busy."}</p>
    </BonesBoundary>
  );
}
```

| Prop          | Maps to        | Notes                                                                                |
| ------------- | -------------- | ------------------------------------------------------------------------------------ |
| `busy`        | `busy`         |                                                                                      |
| `force`       | `force`        | Also renders `aria-busy="true"` and `inert` on the server.                           |
| `delay`       | `delay`        |                                                                                      |
| `minDuration` | `min-duration` |                                                                                      |
| `transition`  | `transition`   |                                                                                      |
| `precision`   | `precision`    | `"css"` or `"measured"`. Enables measured bones (see above).                         |
| `onShow`      | `bones:show`   | Listener. Passing a function from a server component is an error, as with `onClick`. |
| `onHide`      | `bones:hide`   | Same.                                                                                |

The wrapper uses no hooks, so it renders inside server components. Suspense does not need it: a fallback built from the same components with `forceBones` renders `data-bone` markup that the stylesheet styles on its own.

The wrapper normally leaves the output attributes to the element. When `force` is true, it renders `aria-busy` and `inert` so the server paints bones, and React then owns those two attributes and removes them on a later update. The element writes them back while bones are showing. The wrapper also sets `suppressHydrationWarning`, so a boundary that already shows bones by the time React hydrates it is not reported as a mismatch.

The package augments `JSX.IntrinsicElements` with `"bones-boundary"`. A project that already declares the same tag gets a conflicting-declaration error from TypeScript. Delete the local declaration and use this one.

## Browser support

Custom elements, `inert` (Chrome 102, Safari 15.5, Firefox 112), and the `:has()` selector the stylesheet needs. View Transitions are detected at runtime.
